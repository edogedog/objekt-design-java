JUnit-anvisningar – testa din labbkod

JUnit hjälper dig att kontrollera ett beteende i taget och hitta fel medan du arbetar. Använd Eclipse i labsalens Windowsmiljö. Samma arbetsgång fungerar i Eclipse på Mac. Du behöver inte använda terminalen för att köra testerna.

Kom igång i Eclipse på Windows

  1. Ladda ner kodpaketet från laborationssidan. Högerklicka på zip-filen i Utforskaren och välj Extrahera alla. Arbeta i den uppackade mappen.
  2. Öppna Eclipse och välj File → Import → General → Existing Projects into Workspace. Välj den uppackade mappen under Select root directory, markera projektet och välj Finish.
  3. Projektet använder Java 17 och JUnit 5. Om Eclipse visar byggfel, följ felsökningen nedan innan du försöker köra testerna.
  4. Högerklicka på tests-junit i Package Explorer och välj Run As → JUnit Test. Du kan också köra en enskild testklass på samma sätt.
  5. Öppna testnamnen i JUnit-vyn. Markera ett test som misslyckats och läs Failure Trace. Dubbelklicka på en rad för att gå till koden.
  6. Ändra din implementation, spara och kör testerna igen.

Förstå testresultatet

Grönt betyder att de körda testerna klarades. Rött betyder att ett test hittade ett fel eller att ett undantag avbröt körningen. Läs testets namn och jämför förväntat värde (expected) med faktiskt värde (actual) när de visas.

Startpaketet innehåller avsiktligt ofärdiga uppgifter. Därför kan tester vara röda innan du har implementerat funktionerna. Ett kompileringsfel behöver däremot rättas innan testerna kan köras. Gröna tester är ett stöd; du behöver också prova ritprogrammet och kunna förklara din lösning.

Skriv egna tester

Lägg egna tester i en ny klass, exempelvis EgnaFigurTest.java, under tests-junit/grading. Behåll de givna testerna så att du kan fortsätta använda dem som återkoppling. Utgå från en given testklass för importerna och använd @Test från org.junit.jupiter.api.

Varje test skapar sina egna objekt och ska kunna köras för sig. Förklara vilket fel din assertion skulle upptäcka. I labb 1 skriver du ett eget test enligt labbeskrivningen. I labb 2–3 kompletterar du med minst ett meningsfullt test per labb. I labb 4 skriver du ett sekvenstest, till exempel execute–undo–redo, och förklarar tillståndet före och efter operationerna.

Om Eclipse inte kan köra testerna

  • Java saknas eller har fel version: kontrollera projektets Properties → Java Build Path → Libraries och dess JRE System Library. Använd en JDK för Java 17 eller senare med projektets Java 17-inställning. Be handledaren om hjälp om rätt JDK saknas i labsalen.
  • Importerna för JUnit är röda: välj Properties → Java Build Path → Libraries → Add Library → JUnit → JUnit 5. Projektets tester använder JUnit 5.
  • Inga tester hittas: kontrollera att tests-junit är en källkodsmapp i projektets Build Path och att körkonfigurationen använder JUnit 5.
  • Du har lagt till filer utanför Eclipse: högerklicka projektet och välj Refresh, därefter vid behov Project → Clean. Behåll dina egna projektinställningar när du integrerar ett tilläggspaket.
  • Åäö ser fel ut i Java-filer: välj Properties → Resource → Text file encoding → Other: UTF-8 för projektet.

Om du använder Mac

Packa upp zip-filen i Finder och följ sedan samma Eclipse-steg som ovan. Om du har Java installerat men Eclipse inte hittar det, kontrollera Eclipse → Settings → Java → Installed JREs. Välj en JDK som passar projektets Java 17-inställning.

Vilka tester ska du köra?

StarterTest kontrollerar den givna linjen och ritytan och kan köras innan du löst uppgifterna. CircleTest, RectangleTest och SquareTest kontrollerar figurernas kontrakt. I labb 1 kontrollerar DemoContentTest också din egen exempelritning. Från labb 2 tillkommer tester för rörelse, verktyg, grupper och historik enligt respektive labb.

Kör hela tests-junit för samlad återkoppling. Kör också app.DrawingApp och prova det synliga resultatet och de gester som labben beskriver.

Tester och inlämning i CodeGrade

CodeGrade kör samma givna tester i en separat miljö. Följ inlämningsanvisningen i din labb: lämna hela src/ med paketmapparna direkt under. I en zip-fil ska src/ ligga direkt i zip-filens rot, utan extra projektmapp. Lämna inte tests/, tests-junit/, bin/ eller byggskript som bedömningsunderlag. Egna tester tar du med till seminariet.

Ändringar i dina lokala testfiler ändrar inte CodeGrades tester. Använd återkopplingen för att förbättra koden och förbered dig på att förklara både implementationen och dina egna tester vid seminariet.
